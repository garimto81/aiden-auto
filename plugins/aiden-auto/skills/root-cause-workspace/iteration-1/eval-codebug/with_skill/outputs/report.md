# TL;DR — 한 줄 결론

빈 장부에 "더하기"부터 시도해서 죽었습니다. 처음 보는 지역은 칸이 아직 없는데, 코드가 "기존 값에 더하라"고만 해서 없는 칸을 찾다가 멈춘 것입니다.

## 무슨 일이 있었나

지역별 주문 금액을 합산하는 코드를 실행하자, 첫 줄도 못 더하고 바로 멈췄습니다. 화면에는 `KeyError: 'KR'`(키 에러 — 'KR'이라는 칸을 못 찾음)이라는 메시지만 떴고, 합산 결과는 아예 나오지 않았습니다.

## 진짜 원인

`totals`는 금액을 적어 넣는 빈 장부(딕셔너리, dictionary — 이름표가 붙은 칸들의 묶음)입니다. 그런데 코드 4번째 줄 `totals['KR'] += 100`은 "이미 'KR' 칸에 적힌 금액에 100을 더해라"는 뜻입니다.

비유하면, 새 장부를 펴자마자 **"KR 칸에 적힌 숫자에 100을 더하라"**고 시킨 셈입니다. 그런데 KR 칸은 아직 만들지도 않았으니, 더할 원래 숫자가 없습니다. 파이썬은 "그런 칸 없는데요?" 하고 멈춥니다. 두 번째 줄(US)도 같은 이유로 어차피 죽습니다.

`+=`는 "**원래 값을 꺼내서** + 새 값"이라, 원래 값이 있어야만 동작합니다. 첫 등장하는 지역은 원래 값이 없어서 항상 걸립니다.

## 어떻게 알아냈나 (근거)

| 확인한 것 | 발견 |
|----------|------|
| 코드를 그대로 실행 | `KeyError: 'KR'`로 4번째 줄에서 멈춤 — 보내주신 traceback과 동일하게 재현됨 |
| `totals`의 시작 상태 | 2번째 줄에서 `{}`(빈 장부)로 시작 — 어떤 지역 칸도 미리 없음 |
| 멈춘 줄(`totals[o['region']] += o['amount']`) | `+=`가 기존 값을 읽으려는데, 첫 KR 주문 시점엔 'KR' 칸이 없어서 읽기 실패 |
| 수정안을 실제 실행 | 두 방법 모두 정상 동작 확인 — KR이 두 번 나와도 100+20=120으로 올바르게 합산됨 |

## 수정 제안 (아직 적용 안 함)

1. **(가장 권장) 없으면 0부터 시작하게 하기** — 4번째 줄을 아래처럼 바꿉니다. 칸이 없으면 0을 꺼내 쓰므로 첫 등장도 안전합니다. 한 줄만 고치면 되고 import도 필요 없습니다.
   ```python
   totals[o['region']] = totals.get(o['region'], 0) + o['amount']
   ```

2. **(대안) 자동으로 0을 채우는 장부 쓰기** — 합산할 칸이 아주 많다면 더 깔끔합니다. 다만 맨 위에 한 줄(import)을 추가해야 합니다.
   ```python
   from collections import defaultdict
   totals = defaultdict(int)   # totals = {} 대신
   # 4번째 줄은 그대로 totals[o['region']] += o['amount']
   ```

> 두 방법 다 제가 직접 실행해 같은 정답(`{'KR': 120, 'US': 50}`)을 확인했습니다. 한 줄만 고치고 싶으면 1번, 합산 코드를 자주 쓴다면 2번을 권합니다. 적용하려면 알려주세요. 지금은 제안만 한 상태입니다.
