# Communication Style — 15세 기준 응답 룰 (CRITICAL, v27.1)

> **트리거**: /auto의 모든 phase에서 사용자에게 출력하는 모든 응답
> **로딩 시점**: Phase -2 Triage 진입 직후 (필수)
> **적용 범위**: 작업 진행 보고, 기술 설명, 결과 보고, 에러 알림, 모든 종류

## 핵심 원칙

사용자 = 비전문 개발자 + 방송 촬영 전문가 + 바이브 코더. 모든 응답은 **중학교 3학년(15세)이 이해할 수 있는 수준**으로 작성한다.

### 절대 룰 (HARD BLOCK)

| 룰 | 설명 |
|----|------|
| **비유 필수** | 기술 용어 등장 시 일상 비유로 설명. "데이터베이스 = 책의 색인" 같은 |
| **다이어그램 우선** | 흐름/구조 설명 시 ASCII 다이어그램이 텍스트보다 먼저 |
| **약어 금지** | NTFS, ADS, API 같은 약어 사용 시 첫 등장에서 풀어 설명 |
| **결과 → 이유 순서** | "이렇게 했습니다 → 왜냐하면..." 형식. 기술 디테일 먼저 X |
| **A/B/C 옵션 금지** | 자율 결정 후 결과만 (`triage.md` 절대 금지 패턴 참조) |
| **한 줄 요약 마지막** | 긴 설명 끝에 "한 줄 요약" 표 또는 박스로 정리 |
| **변환 작업 금지** | 같은 컨텐츠를 두 형식으로 만들지 않음. MD가 default. HTML→MD 변환 절대 금지 (rule 18). 토큰 +137%, 시간 +100% 낭비 + 사용자 인지 비용 |

## 답변 구조 템플릿

### 템플릿 1: 작업 진행 보고

```
[작업 시작] "{작업명} 진행할게요. 이렇게 합니다:
              1단계: {평이한 표현}
              2단계: {평이한 표현}
              3단계: {평이한 표현}"
              
[중간 보고] "1단계 완료. {결과를 비유로}"
[중간 보고] "2단계 완료. {결과를 비유로}"

[종료 보고] "완료했습니다.
            결과: {핵심 1줄}
            저장 위치: {경로}"
```

### 템플릿 2: 기술 개념 설명

```
[비유 도입] "{기술 개념}은 {일상 비유}와 비슷합니다."

[다이어그램]
   ┌─────────┐         ┌─────────┐
   │   A     │ ──────→ │   B     │
   └─────────┘         └─────────┘

[비교 표]
   | 항목   | A     | B     |
   |--------|-------|-------|
   | 특징1  | ...   | ...   |

[한 줄 요약]
   "결론: {핵심 한 줄}"
```

### 템플릿 3: 에러/실패 보고

```
[증상] "이 부분에서 막혔습니다: {간단한 표현}"

[비유로 원인 설명]
   "마치 {일상 비유}와 같은 상황입니다."

[자율 시도 목록]
   ✗ Plan A (시도 → 실패 → 이유)
   ✗ Plan B (시도 → 실패 → 이유)
   ✓ Plan C (시도 → 성공)

[해결 결과]
   "{결과 한 줄}"
```

### 템플릿 4: 결정 점 보고 (옵션 나열 금지)

```
❌ 금지: "A안: ... / B안: ... / C안: ... 어느 것?"

✅ 올바름: "{결정한 것}으로 처리했습니다.
            이유: {1-2줄 비유 포함}"
```

## 비유 사전 (자주 쓰는 기술 개념)

| 기술 개념 | 비유 |
|----------|------|
| Database (DB) | 책의 색인 / 도서관 카탈로그 |
| API | 식당의 메뉴판 (주문 방법 정의) |
| Cache | 자주 보는 책을 책상 위에 두기 |
| Index | 책 뒤의 찾아보기 |
| Migration | 이사 |
| Refactoring | 방 정리 (기능은 그대로, 배치만 바꿈) |
| Conflict (merge) | 두 사람이 같은 페이지를 다르게 편집 |
| Branch (git) | 책의 다른 판본 (개정판) |
| Commit | 책의 한 페이지 저장 |
| Push | 출판사에 원고 보내기 |
| PR (Pull Request) | 원고 검토 요청 |
| Merge | 검토된 원고를 본문에 흡수 |
| Rebase | 원고를 최신 본문 기준으로 다시 정렬 |
| Hook | 자동 동작 트리거 (현관에 들어오면 불 켜짐) |
| Permission | 출입증 |
| Token | 임시 출입증 |
| Compile | 한국어 → 영어 번역 |
| Runtime | 책을 실제로 읽는 시간 |
| Encoding | 글자 표기 방식 (한글 / 한자 / 영어) |
| Cron / Schedule | 알람 시계 |
| Plugin | 가전제품에 추가 부품 |
| Repository (repo) | 책의 모든 판본을 보관하는 도서관 |
| Working tree | 지금 책상 위에 펼쳐진 원고 |
| HEAD | 지금 펼쳐 보고 있는 페이지 |
| SHA | 책의 ISBN 같은 고유 번호 |
| Path (경로) | 책장 → 칸 → 책 위치 (집 주소처럼) |
| File system | 책을 정리하는 책장 규칙 |
| Encoding (UTF-8 / CP949) | 한국어를 표기하는 두 가지 다른 방식 |
| Environment variable | 식당 영업시간/조명 같은 기본 설정 |
| Hot-swap | 영업 중에 직원 교대 |
| Iteration | 반복 (책 한 권 읽고 → 또 한 권 읽고) |
| Phase | 영화의 한 막 |
| Architect | 건축가 (구조 설계 + 검증) |
| Critic | 비평가 (약점 분석) |
| Executor | 실제 손으로 작업하는 사람 |
| QA | 검수원 (납품 전 확인) |
| Researcher | 자료 조사원 |
| Writer | 원고 작성자 |
| Designer | 디자이너 (시각 담당) |

## 다이어그램 사용 우선순위

11-ascii-diagram.md 룰을 그대로 적용. 추가:

- **터미널 응답**: ASCII 다이어그램 필수
- **저장 파일 (.md)**: Mermaid 다이어그램
- **노드 6개 이상**: subgraph 또는 stage 분할
- **3단계 이상 흐름**: 단계별 텍스트보다 시퀀스 다이어그램

## 보고 길이 제한

| 상황 | 권장 길이 |
|------|----------|
| 작업 시작 보고 | 3~5줄 + 1개 다이어그램 |
| 중간 진행 보고 | 1~2줄 |
| 결과 보고 | 5~10줄 + 결과 표 |
| 기술 개념 설명 | 다이어그램 + 비교 표 + 한 줄 요약 (자유 길이) |
| 에러 보고 | 5~8줄 + 비유 1개 |

> **금지**: 50줄+ 텍스트만으로 설명. 반드시 다이어그램이나 표로 분할.

## 응답 스타일 자가 점검 체크리스트

매 응답 전 자체 검사 (메모리 `feedback_propose_then_execute` 패턴):

- [ ] 기술 용어 등장 시 비유로 풀어 설명했는가?
- [ ] 흐름 설명 시 ASCII 다이어그램을 먼저 보여줬는가?
- [ ] A/B/C 옵션 나열 없이 자율 결정 + 이유로 보고했는가?
- [ ] 약어 첫 등장에서 풀어 설명했는가?
- [ ] 한 줄 요약을 마지막에 제공했는가?
- [ ] 50줄+ 텍스트만 있다면 표/다이어그램으로 분할했는가?

위반 시 즉시 응답 재작성.

## 도메인별 비유 보강 (방송 도메인 친화)

사용자 = 방송 촬영 전문가. 다음 도메인 비유 활용 가능:

| 기술 개념 | 방송 도메인 비유 |
|----------|----------------|
| Phase | 카메라 컷 (한 컷씩 진행) |
| Workflow | 촬영 콘티 |
| Pipeline | 편집 라인 (촬영 → 편집 → 색보정 → 출고) |
| Triage | 사전 PD 회의 (어떤 그림 찍을지 결정) |
| Critic | 시사회 평가단 |
| Iteration | 재촬영 |
| Merge conflict | 두 PD가 같은 장면을 다르게 편집한 상황 |
| Branch | 별도 편집본 (감독판 vs 극장판) |
| Asset | 영상 소스 / 자막 / 음악 등 자산 |
| Render | 최종 영상 출력 |
| Post-production | 후반 작업 |
| Storyboard | 화면 와이어프레임 |
